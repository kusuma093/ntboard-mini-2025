# การกู้คืนเมื่อโปรแกรมค้าง

## พฤติกรรม

- Task Watchdog เฝ้างาน Arduino ตั้งแต่ setup และสั่ง panic/reboot หากงานที่เฝ้าไม่รายงานความคืบหน้าภายใน 120 วินาที โดย feed หลังแต่ละขั้นตอนคืนการทำงาน ไม่มีการ feed จาก task เบื้องหลังเพื่อกลบงานหลักที่ค้าง
- อ่าน RS485 ทีละ transaction ต่อ loop: อุณหภูมิ แล้ว Register มิเตอร์ 10 ตัว สำหรับ SlaveID 1–5 ตามเดิม ถ้าอ่านมิเตอร์ไม่ครบจะไม่ส่งค่าบางส่วน
- พัก 5 นาทีหลังอ่านครบทุกเครื่องด้วย millis() ระหว่างพักยังดูแลเครือข่ายและปุ่มรีเซ็ต การอ่านและเชื่อมต่อแต่ละครั้งยังรอได้หลายวินาที จึงไม่ใช่ระบบตอบสนองทันที
- MQTT ลองเชื่อมต่อครั้งเดียวต่อรอบ เว้นอย่างน้อย 15 วินาทีหลังความพยายามครั้งก่อน มี socket timeout 3 วินาที ส่วน DNS และไลบรารีอาจเพิ่มเวลารอได้ Watchdog เป็นการป้องกันขั้นสุดท้าย
- Ethernet ขอ DHCP ด้วย timeout 5 วินาที/response timeout 1 วินาที ลองใหม่เป็นช่วง ตรวจ lease แทนการเริ่ม DHCP ใหม่ทุกครั้ง เลิกใช้การเข้าถึง Google เป็นเงื่อนไขรีบูต
- เน็ตหรือ broker ล่มจะไม่ทำให้รีบูตวน ยังอ่านและบันทึก SD ได้หาก SD ใช้งานได้ **ข้อมูลระหว่าง offline ไม่ได้ส่งย้อนหลังอัตโนมัติ**
- NTP ลองครั้งเดียวแล้วกลับมาลองทุก 60 วินาที ถ้าไม่ได้เวลาจะไม่เขียนทับ RTC หากไม่มี RTC จะใส่ TIME_UNAVAILABLE ใน log
- GPIO 5 เลือกโหมด Ethernet/Wi-Fi ตอนเปิดเครื่อง หากเปลี่ยน jumper ต้องรีบูต
- หน้า Wi-Fi มีเวลารอเชื่อมต่อเริ่มต้น 10 วินาที และจำกัดช่วง captive portal โดย deadline 30 วินาทีนับก่อน Portal.begin(); หน้าเว็บยังให้บริการจาก loop หลังจากนั้น
- แสดงและบันทึก Boot reset reason เป็นรหัส esp_reset_reason() ใน Serial และ SD
- ยังไม่มีรีเซ็ตเที่ยงคืน ส่วน OTA เพิ่มภายหลัง ดู `docs/ota.md` (ต้องลงทะเบียนและ provision ก่อนใช้งาน)

## ความเข้ากันได้

Topic, JSON, ลำดับ Register, SlaveID และการแบ่งข้อมูลไฟฟ้าเป็นชุดละ 5 ค่าเหมือนเดิม รวมถึง Topic อุณหภูมิที่ผู้ใช้เปลี่ยนเป็น energy ไว้แล้ว

SD log เปลี่ยนจากอ่านหน่วยความจำเกินขอบเขตเป็น 10 ค่าสำหรับมิเตอร์ และ 2 ค่าสำหรับอุณหภูมิ ปรับบัฟเฟอร์วันที่ให้พอและแก้ปี RTC ให้เป็นปีนับจาก 1900 ตามสัญญาของไลบรารี

แก้ Artron_RTC::begin() ให้คืน false เมื่อไม่พบ RTC และเติมวงเล็บปิดที่ขาดใน FileSysTemOperations.cpp เพื่อให้ build ได้

## การตรวจบนเครื่องพัฒนา

ใช้ `pio run` สำหรับ env esp32dev (Arduino ESP32 2.0.17 ที่ติดตั้งอยู่) ไม่ได้อัปโหลดลงบอร์ดจากการทดสอบนี้

## การตรวจบนบอร์ดก่อนใช้งานจริง

1. ต่อมิเตอร์และเซนเซอร์ ตรวจ Topic/JSON ทั้งสองชุดของมิเตอร์เทียบเวอร์ชันเดิม และตรวจว่าหลังจบรอบพัก 5 นาที
2. ถอด LAN หรือปิด AP ทั้งตอนบูตและระหว่างทำงาน: ยังมี log เซนเซอร์ใน SD ไม่รีบูตวน ต่อกลับแล้ว MQTT กลับมาส่งในรอบอ่านถัดไป ทดสอบทั้งสองโหมด
3. ปิด broker หรือบล็อก DNS: ยังอ่านเซนเซอร์ต่อ และเว้นช่วงการเชื่อมต่อใหม่
4. บล็อก NTP: บูตได้โดยใช้ RTC เดิม ถอด RTC ด้วยแล้วต้องบูตได้และรายงาน TIME_UNAVAILABLE
5. ถอด RS485: การอ่าน timeout แล้วไป SlaveID ถัดไป ไม่ส่งมิเตอร์ที่อ่านไม่ครบ
6. เปิดหน้าตั้งค่า Wi-Fi ค้างไว้โดยยังไม่เชื่อมเครือข่าย: การอ่านเซนเซอร์ต้องเริ่มได้และหน้าเว็บยังใช้งานได้
7. ทดสอบ Watchdog บนบอร์ดสำรองเท่านั้น: ใส่ `while (true) { delay(100); }` ชั่วคราวในขั้นอ่านเซนเซอร์โดยไม่ feed watchdog ต้องรีบูตและแสดงเหตุผล watchdog; เอาโค้ดจำลองค้างออกก่อนใช้งานจริง
8. ปล่อยทำงานต่อเนื่องอย่างน้อย 24 ชั่วโมง ตรวจว่าไม่มีรีเซ็ตระหว่างอ่านปกติ และทดสอบปุ่ม GPIO 0 ระหว่างพักรอบ

Build ผ่านไม่ได้ยืนยันการรีเซ็ตทางฮาร์ดแวร์จริงหรือการฟื้นตัวของอุปกรณ์ต่อพ่วงที่เสียทางไฟฟ้า
