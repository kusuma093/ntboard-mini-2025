# OTA แบบไฟล์กลาง — 1.0.0-ota.4

## ติดตั้งฝั่งเซิร์ฟเวอร์ครั้งเดียว

1. นำ API/Angular รุ่นใหม่ขึ้นเซิร์ฟเวอร์
2. รัน `webapi/sql/20260924_ota_enrollment.sql` ในฐานข้อมูลเดียวกับตาราง OTA เดิม (หากยังไม่มีตารางเดิม ต้องรัน `20260922_ota.sql` ก่อน) สคริปต์นี้เพิ่มเฉพาะ `ota_enrollments` ไม่แก้ข้อมูลมิเตอร์
3. คัดลอกไฟล์ `webapi/.ota/enrollment-private.pem` จากเครื่องพัฒนา ไปไว้ `/home/nt_ifbd/webems/OTAData/enrollment-private.pem` บนเซิร์ฟเวอร์ ใช้ SFTP และให้บัญชีที่รัน API อ่านได้ เก็บไฟล์นี้เป็นความลับและสำรองไว้ ไม่วางใน wwwroot หรือส่งให้บอร์ด
4. Docker Compose ของ API ผูก OTAData ที่พาธเดียวกันไว้แล้ว จึงไม่ต้องแก้พาธภายใน container
5. Build ใหม่ทั้ง API และ Angular:

```bash
cd /home/nt_ifbd/webems/sandox-dotnet-core/webapi
docker compose up -d --build sfom-api
cd /home/nt_ifbd/webems/iot_Angular
docker compose up -d --build sfom-app
```

ไฟล์ private key นี้จับคู่กับ public key ใน `include/OtaEnrollment.h` ของเฟิร์มแวร์กลาง ห้ามสร้างกุญแจใหม่ทุกครั้งที่ deploy มิฉะนั้นบอร์ดที่ยังไม่จับคู่จะลงทะเบียนไม่ได้ ไฟล์ private key ถูกกันออกจาก Git และ Docker build context แล้ว

## รับบอร์ดใหม่

1. ไม่ต้องมี `OtaConfig.local.h` ใช้โปรเจกต์/เฟิร์มแวร์กลาง 1.0.0-ota.4 แฟลช USB ครั้งแรกด้วย PlatformIO Upload (ไฟล์ firmware.bin เดี่ยวเป็น application image ไม่ใช่ไฟล์รวม bootloader/partition)
2. ต่อ LAN หรือกำหนด Wi-Fi ตามวิธีเดิม บอร์ดต้องเข้าถึง `http://broker.ntplc.co.th:8080/ota-api/` ได้
3. เปิด `/ems/ota` เข้าระบบ admin รอจบรอบสแกนเซนเซอร์แรก บอร์ดจะปรากฏในรายการรออนุมัติ
4. ตรวจ MAC ให้ตรงเครื่องแล้วกด **รับบอร์ด** และตั้งชื่อ ระบบจับคู่ให้ในรอบตรวจถัดไปประมาณ 1 นาที
5. รอเวอร์ชัน/พื้นที่ OTA ปรากฏ จึงสั่งอัปเดตได้

บอร์ดสร้างกุญแจสุ่มของตัวเอง เก็บใน NVS และส่งแบบ RSA-OAEP SHA256 ให้เฉพาะเซิร์ฟเวอร์ที่ถือ private key เปิดอ่านได้ คำตอบยืนยันด้วย HMAC และ nonce ป้องกันคำตอบเก่า ไม่ฝังกุญแจลับร่วมในไฟล์กลาง

การลงทะเบียนครั้งแรกยังต้องให้ผู้ดูแลตรวจตัวตนบอร์ด: MAC เป็นชื่อระบุเครื่อง ไม่ใช่หลักฐานตัวตน หากมี MAC ซ้ำ/คำขอไม่รู้จัก อย่าอนุมัติ ควรรับบอร์ดในเครือข่ายที่ควบคุมได้ หน้าผู้ดูแลใช้ HTTPS หรือเครือข่ายจัดการที่เชื่อถือได้ตามเดิม

บอร์ดที่มี config/key เดิมยังใช้งานต่อ ไม่เปลี่ยนกุญแจอัตโนมัติ รายการที่ลงทะเบียนไว้แต่ยังไม่เคยติดต่อและไม่มีงาน สามารถรับคำขอใหม่ผ่านหน้าเว็บได้ บอร์ดที่จับคู่แล้วจะไม่ถูกแทนกุญแจด้วยคำขอใหม่ หากล้าง NVS ต้องจัดการกู้คืนต่างหาก อย่าล้าง NVS เพื่อแก้ปัญหาทั่วไป

## อัปเดตและคืนเฟิร์มแวร์โรงงาน

1. เลือก `firmware.bin` หน้าเว็บอ่านเวอร์ชันให้เอง แล้วกดอัปโหลด
2. เลือกเวอร์ชันและบอร์ด กดสั่งอัปเดต บอร์ดตรวจผ่าน MQTT/HTTP ตามเดิมและรีบูตเมื่อสำเร็จ
3. หลังทดสอบรุ่นที่ต้องการแล้ว เลือกเวอร์ชันนั้น กด **ใช้เวอร์ชันที่เลือกเป็นเฟิร์มแวร์โรงงาน**
4. ปุ่มคืนค่าโรงงานจะติดตั้งรุ่นมาตรฐานที่กำหนดผ่าน OTA โดยไม่ล้างค่าเครือข่ายหรือกุญแจ รุ่นมาตรฐานเก็บใน `OTAData/factory-release.txt` และไฟล์ .bin ใน `OTAData/firmware` ต้องสำรองทั้งโฟลเดอร์

ไฟล์นี้เป็นเฟิร์มแวร์โรงงานที่ดาวน์โหลดคืนจากเซิร์ฟเวอร์ ไม่ใช่ partition โรงงานถาวรหรือ bootloader rollback บอร์ดที่บูตไม่ขึ้นยังต้องกู้ผ่าน USB

## ตรวจปัญหา

- `OTA automatic enrollment ready`: เริ่มรอจับคู่อัตโนมัติ
- `OTA waiting for approval on web page`: ติดต่อ API ได้ รอรับบอร์ดบนเว็บ
- `OTA enrollment approved; device configuration saved`: จับคู่สำเร็จ
- `OTA enrollment unavailable; retry in one minute`: ตรวจ API URL, ตารางใหม่, private key ที่ต้องตรงกับ firmware และ log API
- API ขึ้น `Enrollment server key not installed`: ยังไม่ได้วาง enrollment-private.pem ใน OTAData

งานนี้ไม่เปลี่ยนคำสั่งอ่านมิเตอร์ MQTT topic หรือ JSON เซนเซอร์ และไม่รัน SQL/แฟลช/deploy โดยอัตโนมัติ ต้องทดสอบกับบอร์ดจริงก่อนใช้หลายเครื่อง
