# OTA ผ่าน HTTP

## ของที่เพิ่ม

- บอร์ด: `src/OtaClient.cpp` ใช้ได้ทั้ง Wi-Fi และ Ethernet W5500 ผ่าน TCP client แยกจาก MQTT
- Web API: `webapi/Controllers/OtaController.cs` และ `webapi/Ota/` ในโปรเจกต์ sandox-dotnet-core
- Angular: หน้า `/ems/ota` และปุ่มเข้าใช้งานจากหน้าจัดการเฟิร์มแวร์เดิม
- ฐานข้อมูล: SQL `webapi/sql/20260922_ota.sql` เพิ่ม `ota_devices`, `ota_releases`, `ota_jobs` เท่านั้น ผู้ดูแลต้องรันเอง

ไม่เปลี่ยนรูปแบบ JSON/Topic มิเตอร์ ไม่แก้ฐานข้อมูลจริง และยังไม่แฟลชบอร์ดจากขั้นตอนพัฒนา

## เปิดใช้งานครั้งแรก

1. ผู้ดูแลตรวจและรัน SQL ในฐานข้อมูล MySQL `iot_sandbox`
2. เพิ่มส่วน `Ota` จาก `webapi/appsettings.Ota.example.json` เข้า configuration ที่ deploy จริง (ไฟล์ example ไม่ได้โหลดเอง)
   - ตั้ง `Enabled: true` หลังสร้างตาราง
   - ใส่ `AdminCustomerIds` เป็นเลข Seq ของบัญชีผู้ดูแลเดิมที่จะให้สิทธิ์ OTA ถ้าว่างจะไม่มีใครเข้าได้
   - ตั้ง `StoragePath` เป็นโฟลเดอร์ถาวรที่ API เขียนได้ เช่น `/app/api-data/ota` และสำรองทั้งไฟล์เฟิร์มแวร์กับโฟลเดอร์ keys
3. Deploy API/Angular แล้วเปิด `/ems/ota` ล็อกอินด้วยบัญชีที่อนุญาต
4. ลงทะเบียน MAC ที่บอร์ดแสดงใน Serial (ไม่มี 01/02 และ SlaveID ต่อท้าย) เก็บกุญแจที่แสดงครั้งเดียว
5. กำหนด HTTP URL ที่บอร์ดเข้าถึงได้ แล้วดาวน์โหลด `OtaConfig.local.h` ใส่ไว้ใน `include/` ของโปรเจกต์นี้
6. Build และแฟลชผ่าน USB ลงบอร์ดที่ MAC ตรงกันครั้งแรก บอร์ดจะเก็บ host/port/path/key ใน NVS และจะไม่เขียนทับ config ที่มีอยู่
7. รออ่านเซนเซอร์ครบหนึ่งรอบ ตรวจหน้าเว็บว่าพบ MAC/เวอร์ชัน/พื้นที่ OTA แล้ว

ตัวอย่าง URL `http://10.1.220.133:5000/` มาจาก environment ของ Angular ต้องยืนยันว่าบอร์ดแต่ละสถานที่เข้าถึง IP นี้ได้

## อัปเดตออนไลน์ครั้งถัดไป

1. นำ `include/OtaConfig.local.h` ออกก่อน build ไฟล์สำหรับเผยแพร่ กุญแจบนบอร์ดยังอยู่ใน NVS
2. เปลี่ยนเวอร์ชันใน `include/OtaVersion.h` เป็นค่าใหม่ เช่น `1.0.1`
3. Build ด้วย `pio run` แล้วอัปโหลด `.pio/build/esp32dev/firmware.bin` ที่หน้า OTA ใส่เวอร์ชันตรงกับที่ build ห้ามใช้ bootloader/partitions/ไฟล์รวมทั้งแฟลช
4. เลือกเวอร์ชันและบอร์ดทดลองหนึ่งเครื่อง แล้วกดสั่งอัปเดต
5. บอร์ดตรวจงานเมื่อได้รับ MQTT แจ้งเตือนหรือเชื่อมต่อ MQTT ใหม่ และตรวจสำรองทุก 1 ชั่วโมงในช่วงพักระหว่างรอบอ่าน ดาวน์โหลด → ตรวจ SHA-256 → เปลี่ยนช่องบูต → รีบูต
6. หลังบูตเวอร์ชันใหม่และจบรอบอ่านแรก จะรายงานสำเร็จ หน้าเว็บไม่ถือว่าการส่งคำสั่งเท่ากับติดตั้งแล้ว

## การป้องกันข้อมูลบน HTTP

คำขอและข้อมูล manifest ใช้ HMAC-SHA256 กับกุญแจรายบอร์ด และมี counter ที่เก็บข้ามการบูตเพื่อตรวจคำขอ/คำตอบเก่า ไฟล์ถูกตรวจเทียบ hash ที่อยู่ใน manifest ที่ยืนยันแล้วก่อนเปิดใช้งาน ไม่ส่ง device key ไปกับคำขอของบอร์ด

HTTP ไม่เข้ารหัสการล็อกอินผู้ดูแลหรือการแจกกุญแจครั้งแรก ควรเข้าหน้า Admin/API สำหรับผู้ดูแลผ่าน HTTPS หรือเครือข่ายจัดการที่เชื่อถือได้ ส่วนปลายทางของบอร์ดยังคงเป็น HTTP ได้ตามที่กำหนด คำขอดาวน์โหลดมีลายเซ็นและต้องตรงกับงานที่กำลังทำ แต่ไฟล์ยังไม่ถูกเข้ารหัสบนสาย จึงควรใช้เครือข่ายที่เชื่อถือได้หรือ VPN

API ปฏิเสธ provisioning image ที่มี key ฝังอยู่ ป้องกันนำไฟล์เฉพาะเครื่องไปเผยแพร่เป็นไฟล์รวม ทุก release ใช้เวอร์ชันไม่ซ้ำ

## ข้อจำกัดที่ต้องทราบ

- การดาวน์โหลดหยุดอ่านเซนเซอร์ชั่วคราว อาจใช้ได้สูงสุด 10 นาที ก่อน timeout และยกเลิก ข้อมูลที่ขาดไม่ได้ส่งย้อนหลังเอง
- ดาวน์โหลดขาด/ไฟล์เสียไม่เปิดใช้ช่องใหม่ แต่ **ยังไม่มี bootloader rollback อัตโนมัติที่รับประกันได้เมื่อเฟิร์มแวร์ใหม่บูตแล้วพัง** ต้องทดสอบบอร์ดสำรองและเตรียม USB กู้คืน
- อย่าลบ NVS เพราะมี config/key/counter ห้ามเปลี่ยน partition layout ผ่าน OTA รุ่นนี้
- ต้องคง Content-Length และ X-Ota-Signature ที่ proxy ห้ามบีบอัด/redirect/chunked response สำหรับ endpoint บอร์ด
- ยังต้องทดสอบ Wi-Fi, LAN, ไฟดับระหว่างอัปเดต, ไฟล์ถูกแก้ และการทำงานมิเตอร์จริงก่อนนำไปใช้หน้างาน
- API มีคู่มือรายละเอียดใน `webapi/docs/OTA.md` และชุดทดสอบ offline ใน `tests/Ota.ProtocolTests`

## ปุ่มย้อนกลับและคืนค่าโรงงานบนเว็บ

- **ย้อนกลับเฟิร์มแวร์**: API เลือก release ล่าสุดที่บอร์ดนี้เคยรายงาน Succeeded และต่างจากเวอร์ชันปัจจุบัน หากไม่มีประวัติ (เช่นรุ่นแรกแฟลชผ่าน USB) ปุ่มจะยังใช้ไม่ได้ สามารถเลือกไฟล์รุ่นเก่าที่ตรวจสอบแล้วผ่านปุ่มสั่งอัปเดตได้
- **คืนค่าโรงงาน (เฟิร์มแวร์)**: ดาวน์โหลด release มาตรฐานจากเซิร์ฟเวอร์ ไม่ล้าง NVS, Wi-Fi, LAN หรือกุญแจ OTA และไม่ใช่ factory partition ถาวร
- ตั้งค่า `Ota:FactoryVersions:ntboard-mini-2025` ใน config API เป็นเวอร์ชันที่ทดสอบแล้วและอัปโหลดไว้ เช่น `1.0.0-ota.1` ค่าเริ่มต้นว่างทำให้ปุ่มยังใช้ไม่ได้ ตัวอย่าง config ไม่ถูกโหลดอัตโนมัติ ต้องรวมเข้ากับ config ที่ใช้งานจริงและ restart API
- หน้าเว็บแสดงเวอร์ชันเป้าหมายและขอยืนยันก่อนเข้าคิว API ตรวจเป้าหมายอีกครั้ง ป้องกันใช้ข้อมูลเก่าจากหน้าเว็บ
- ใช้ตารางและโปรโตคอล OTA เดิม ไม่ต้องเพิ่ม SQL สำหรับฟีเจอร์นี้ และไม่ต้องเปลี่ยนโค้ดมิเตอร์
- ต้องเก็บไฟล์ release มาตรฐานใน storage ถาวรของ API รวมถึงกุญแจที่ใช้ถอดรหัส device key
- งานเดิมต้องจบก่อนส่งงานกู้คืน งาน Queued ยกเลิกได้ แต่งาน Downloading ห้ามบังคับแทรกเพื่อป้องกันแข่งกันเขียนแฟลช หากงานค้างและบอร์ดติดต่อไม่ได้ต้องตรวจบอร์ด/กู้ผ่าน USB
- ทั้งสองปุ่มเป็น **การดาวน์โหลดรุ่นเก่าผ่าน OTA โดยผู้ดูแล** ไม่ใช่ automatic boot rollback; บอร์ดต้องยังบูตและเรียก API ได้ เฟิร์มแวร์เป้าหมายต้องรองรับ OTA และใช้ partition/NVS ที่เข้ากันได้
- ก่อนใช้งานจริง: บอร์ดทดลองติดตั้ง A แล้ว B จน Succeeded → กด rollback ต้องกลับ A; ตั้ง A เป็น factory แล้วกดจาก B ต้องกลับ A; ตรวจ MQTT และค่าการเชื่อมต่อหลังรีบูต; ทดลองปุ่มขณะมีงานค้างและขณะบอร์ด offline (ต้องไม่รายงานว่าสำเร็จ)



## MQTT แจ้งเตือน OTA (ตั้งแต่ 1.0.0-ota.2)

- บอร์ด subscribe `ems/{MAC}/ota/notify` ผ่าน MQTT connection เดิม ไม่เปลี่ยน topic/JSON ของค่ามิเตอร์
- API บันทึกงานก่อน แล้วส่งข้อความ `check` แบบ QoS 1 ไม่ retained ไปยังบอร์ดนั้น รวมถึงงาน rollback/factory restore
- MQTT เป็นเพียงการแจ้งให้ตรวจงาน ไม่ใช่สิทธิ์ติดตั้ง ต้องผ่าน signed HTTP manifest และตรวจ SHA-256 ตามเดิม
- ตรวจครั้งแรกและหลัง MQTT reconnect; ข้อความซ้ำรวมเป็นธงเดียวและตรวจ HTTP ไม่ถี่กว่า 60 วินาที เริ่มตรวจเฉพาะช่วงพักระหว่างรอบเซนเซอร์
- เมื่อไม่มีงาน ตรวจสำรองทุก 1 ชั่วโมง เมื่อมีผลติดตั้งรอส่ง/รอยืนยัน ตรวจได้ทุก 60 วินาที
- API ใช้ `Ota:Mqtt` (Enabled, Host, Port, Username, Password) ให้ตรงกับ broker ของบอร์ด และบัญชี API ต้องมีสิทธิ์ publish topic แจ้งเตือน บอร์ดต้องมีสิทธิ์ subscribe topic ของตัวเอง
- หาก broker ใช้งานไม่ได้ API จำกัดเวลาส่งแจ้ง 5 วินาที งานที่บันทึกแล้วไม่ถูกยกเลิกและไม่สร้างซ้ำ; บอร์ดยังตรวจผ่าน HTTP สำรองได้
- ต้อง deploy API และติดตั้ง firmware 1.0.0-ota.2 เพื่อใช้ MQTT รุ่นเดิมยังตรวจทุก 5 นาทีและรับการอัปเดตเป็นรุ่นใหม่ผ่านวิธีเดิมได้
- ยังต้องทดสอบบนบอร์ดจริงทั้ง LAN/Wi-Fi, reconnect, MQTT ACL และข้อมูลมิเตอร์หลังอัปเดต
