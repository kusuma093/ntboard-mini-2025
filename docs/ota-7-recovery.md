# 1.0.0-ota.7 — การฟื้นการเชื่อมต่อ

เพิ่มการกู้คืนเมื่อ network/MQTT หลุด หรือคำสั่ง publish ล้มเหลว:

- ต่อ MQTT ใหม่ทุก 15 วินาทีตามเดิม
- เมื่อผิดปกติต่อเนื่อง 3 นาที ปิด socket ของ MQTT/OTA แล้วเริ่ม Ethernet DHCP ใหม่ หรือสั่ง Wi-Fi reconnect และลองใหม่ทุก 3 นาที
- ถ้ายังผิดปกติต่อเนื่อง 30 นาที รีบูตบอร์ด เมื่อบูตใหม่เริ่มนับเวลาใหม่ จึงอาจรีบูตทุกประมาณ 30 นาทีหากเครือข่ายภายนอกยังเสีย
- ทุก 5 นาที บันทึก HEALTH ใน Serial และ SD /log.txt: uptime, heap, network, MQTT, จำนวนส่งสำเร็จ/ล้มเหลว, อายุข้อมูลส่งล่าสุด และจำนวนอ่าน Modbus สำเร็จ/ล้มเหลวแยกพอร์ต
- บันทึก RECOVERY ก่อนกู้คืนและหลังบูตจากการกู้คืน
- ปิด socket OTA ก่อนเริ่ม W5500 ใหม่ เพื่อไม่ให้เก็บหมายเลข socket เก่าข้ามการเริ่มเครือข่ายใหม่

ช่วงอ่านยังรอ 2 นาทีหลังครบหนึ่งรอบ JSON/topic/การแบ่งชุดมิเตอร์เหมือน .6
การกู้คืนทำใน main loop นอกช่วงติดตั้ง OTA ไม่รีบูตกลางการเขียนเฟิร์มแวร์ด้วยเงื่อนไขนี้

ข้อจำกัด: publish สำเร็จเป็นผลของ MQTT client ไม่ใช่การยืนยันจาก DB จึงตรวจการหยุดของตัวรับ InfluxDB ไม่ได้ การอ่านเซนเซอร์ล้มเหลวเพียงอย่างเดียวไม่กระตุ้น network recovery และไม่มีการส่งข้อมูลย้อนหลัง

ทดสอบบนบอร์ดจริงหลังติดตั้ง:
1. ยืนยันเวอร์ชัน .7 แล้วปล่อยทำงานโดยไม่เปิด/ปิด Monitor ตรวจข้อมูลใหม่หลายรอบ
2. ถอด LAN เกิน 3 นาทีแล้วเสียบกลับ ตรวจ RECOVERY และข้อมูลกลับเข้า MQTT/DB โดยไม่กดรีเซ็ต
3. ทดสอบการขาดเครือข่ายเกิน 30 นาทีในช่วงที่ยอมให้ข้อมูลขาดได้ ตรวจเหตุผลรีบูต จากนั้นเชื่อมเครือข่ายกลับ
4. เปิดทิ้งไว้ 48 ชั่วโมงและเก็บ /log.txt จาก SD หากข้อมูลขาดอีก เพื่อเทียบ uptime, สถานะ MQTT และ Modbus

CSV วันที่ 24–26 กันยายนยืนยันช่องว่างใน DB แต่ยังไม่ยืนยันสาเหตุเดิม การแก้รุ่นนี้เพิ่มการฟื้นและหลักฐานวิเคราะห์ ไม่ใช่ผลยืนยันว่าทดสอบระยะยาวผ่านแล้ว
